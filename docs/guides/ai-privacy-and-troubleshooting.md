# AI Privacy and Troubleshooting

## Browser Credential Limits

AI requests use the connection route explicitly selected in provider settings. **Direct** (the default) connects this browser to the provider. **Open 3D gateway** and **Self-hosted gateway** also send provider credentials, messages, images and transmitted scene context through the selected relay. Open 3D does not supply a model account or pay provider usage charges. An API key is optional and, when saved, is stored in this browser's local storage.

The Open 3D gateway is available when provided by the website. Its application code does not persist, cache or analyze AI content. Forwarding necessarily uses transient memory; short-lived security metadata and infrastructure/provider processing policies still apply. This is not a claim of infrastructure-wide zero retention. Self-hosted users must verify the operator and data security themselves. See [Connection routes](modra-connection-routes.md) and [gateway deployment](../../apps/ai-gateway/README.md).

Local storage is not a secure secret store. Any JavaScript running in the page origin, including compromised application code or a browser extension with sufficient access, may be able to read it. Do not save a credential in a shared browser profile or use a key with permissions or spending limits you are unwilling to expose to that page. Remove the saved key in AI provider settings when it is no longer needed. Provider keys and self-hosted gateway tokens have independent removal controls; removal cancels in-flight work and prevents old credentials from being reused by retries or continuations. It deletes the browser's saved copy, not the credential at the provider or gateway. Open 3D gateway access grants are short-lived and memory-only.

Open provider settings from the floating Modra workspace. The expandable **Safety notice** explains that configuration and credentials stay in the browser and require a secure environment. Protocol is independent of model choice; a protocol does not guarantee that a particular model supports images or tools.

| Protocol           | Base URL example                                   | Native request                                                         |
| ------------------ | -------------------------------------------------- | ---------------------------------------------------------------------- |
| OpenAI-compatible  | `https://api.openai.com/v1`                        | Chat Completions                                                       |
| OpenAI Responses   | `https://api.openai.com/v1`                        | Responses, with `store: false` and complete local conversation history |
| Anthropic Messages | `https://api.anthropic.com/v1`                     | Messages with `x-api-key` and the API version header                   |
| Gemini             | `https://generativelanguage.googleapis.com/v1beta` | Streaming generateContent with `x-goog-api-key`                        |

Enter the base URL, not the final operation path. URLs cannot contain embedded credentials, query parameters or fragments. Gemini keys are never sent in the URL. Direct access still requires a provider that allows browser requests; choosing a native protocol does not bypass CORS. Responses does not require a hosted thread or provider-stored response to continue; optional response storage is disabled on each request. This is not a zero-retention guarantee for the provider. See the [OpenAI Responses migration guide](https://developers.openai.com/api/docs/guides/migrate-to-responses).

Changing protocols rebuilds compatible history from local semantic messages, tool results and actual application outcomes. It does not execute historical commands again. Required opaque tool-continuation metadata is reused only with its original protocol, not displayed as assistant prose or sent to a different protocol. Declared text-only models reject image-bearing history before network dispatch; unrecognized models have unknown capabilities and may still be rejected by the provider. There is no automatic model or protocol fallback.

Valid legacy settings migrate locally to the version-two format with Direct as their route; migration does not change approval mode or send a request. A failed migration leaves the old record intact and displays a storage warning. Credential removal sanitizes both current and rollback records, using a separate revocation marker to prevent stale-record recovery after an interrupted cleanup. Retry removal if a cleanup error is shown; do not run older software against incompletely cleaned credential records.

The configured provider receives the prompts, attached images, and prior conversation context sent for a request. Session messages, drafts, tool records and image Blobs are saved in the separate browser-local `open-3d-modra` IndexedDB database when available. They are not part of project files or glTF exports and are not uploaded just to reopen a session. In memory-only mode they last only for the current page. Images remain part of follow-up context until earlier turns are summarized; summarized images remain local but are not resent unless attached again. Automatic compaction uses a separate, potentially billable request through the configured AI service; see [Context window and automatic compaction](modra.md#context-window-and-automatic-compaction). If the model calls a registered scene query, the returned query data is also sent to the provider so it can continue the conversation. Queries return only bounded serializable data from the active document; renderer objects and arbitrary application memory are not exposed. The provider may retain or process request data according to its own terms and configuration.

## Local Sessions and Scene Safety

Sessions belong to a saved local project or the current unsaved workspace, not merely its document identifier. First scene save normally links that workspace's history to the new saved project; duplicate/import creates independent history. Session controls offer create, rename, open and delete. Reopening loads local text/images without making an AI request. Your draft is retained when switching; active tasks and unconfirmed proposals require explicit stop/discard confirmation. Closing the floating window alone keeps the task running in the page.

Previously active work is interrupted after reload, not automatically resumed. Recovered proposals cannot be applied directly and approval defaults to Request approval. Applied conversation history is **not a scene backup**: scene saving remains explicit. If applied changes were never saved with the scene, their historical decision remains, but the current effect is unknown. Even matching object names/IDs do not prove an effect survived. No history recovery automatically restores a scene or replays commands.

Only one tab writes each session. Another tab can inspect a live owner's history but cannot send, approve or change its draft. Use a new session, or explicitly choose a separate memory session. A suspended tab can lose its lease; its old work stops rather than committing without ownership. There is no forced live takeover or multi-user scene collaboration.

Storage-error, read-only and memory-only indicators describe local durability; routine save progress is not shown. Quota failures preserve active in-memory content and images; **Retry local save** does not repeat AI requests or modeling changes. Unavailable, corrupt or newer storage is not overwritten: use the separate memory session and retain/export your scene. Browser deletion or profile loss removes local data; memory-only work is lost on page reload. Native scene save/open remains independent when session storage is unavailable, but a warning explains when history cannot be associated.

Session lists show only the current project. Abandoning an unsaved workspace removes its temporary sessions and unreferenced images; later visits can recover interrupted cleanup under writer-lease and Web Lock checks. Legacy unrelated history is not scanned. Session deletion removes its local transcript/draft and images not referenced elsewhere. Project deletion additionally discloses removal of associated Modra data, stops active work and invalidates previews before removal; an open scene remains unsaved with a fresh history scope. Cleanup failures remain sealed and retryable in Projects. If native removal failed safely, explicit cancellation can unlock history under a new epoch, never revive old execution. Successfully saved project histories are retained until explicitly deleted.

Local storage is not encrypted against scripts running on this origin. Session persistence excludes provider keys and gateway tokens, but prompts or images you deliberately enter can themselves contain sensitive material. Do not place secrets in a prompt, and do not treat copy-message as a sanitized diagnostic export. Native/glTF exports and application-generated diagnostics do not include session records or saved credentials. The existing Umami script and public promotion assets have their own network metadata; Modra does not send content through custom analytics events or session-replay hooks.

## Approval Modes and Reference Images

The conversation defaults to **Request approval**. Review proposed changes on the canvas, then accept or reject each batch. **Auto-approve** applies completed batches without asking and continues the modeling task. Each applied batch is one undoable edit. Task mode and approval policy are captured when a task is sent or queued. Changing composer controls affects future tasks, not active work or an existing proposal. Automatic approval pauses after 20 consecutive batches so you can review the scene before continuing.

Use **Add images** to attach multiple reference views, preview them, or remove them before sending. Image-only messages are supported. Each message accepts up to five JPEG, PNG, WebP, or GIF images, up to 5 MB each. The selected model must support image input as well as tool calling; support varies by provider and model.

## Connection Retries and Tool Activity

Failed connections automatically retry up to five times after the initial attempt. The conversation shows **Reconnecting 1/5** through **5/5**, and **Cancel request** stops both reconnecting and the current request. Retries use exponential backoff (1, 2, 4, 8, and 8 seconds). Transient HTTP responses (408, 429, 500, 502, 503, and 504) also retry; a provider's `Retry-After` header can extend the wait to at most 60 seconds. Authentication, invalid configuration, and tool validation errors do not retry.

Retries operate on each failed HTTP connection, including follow-up requests within a modeling task. They resend the same request context without replaying completed tool calls or applying changes twice. An already established response stream that fails partway through is not replayed: the provider protocol does not support safe stream resumption. Streamed text and valid proposals remain available for review as described below.

Each assistant reply lists its **Tool calls**, including scene queries and modeling commands. Expand a call to inspect its parameters and result. Statuses distinguish preparing, running, completed, failed, and cancelled calls. A completed modeling tool means its preview was generated, not that its changes were applied; the current approval mode still controls application. Failed calls remain visible for inspection, and tool errors stop further tool rounds.

## Sponsored Providers

Workspace startup preloads a public provider promotion list from `https://oss.xiaohe.ink/sponsors/special/open-3d.json` once per page session. The request and its result are cached only in memory; reopening settings reuses them, and refreshing the page allows a new request. Provider logos load from the URLs in that list. These requests do not include your saved AI configuration, API key, prompts, or scene data; the remote hosts still receive standard network information such as your IP address. Promotion links open the provider's website in a new tab and may contain referral parameters. They do not configure a provider or change your settings. Provider availability, pricing, and privacy terms are determined by the provider. If the list is unavailable, settings remain usable without promotions; refresh the page to retry.

## Message Presentation and Copying

Assistant Markdown never executes raw HTML or automatically loads external images. Only absolute HTTP/HTTPS links without embedded credentials are navigable; links open separately with no referrer. Very long replies (over 65,536 characters) use a full, untruncated plain-text view instead of Markdown parsing. Copy message/code writes only the selected text to your clipboard on explicit action. Copying neither replaces your draft nor sends a request. Pasting image files into the composer reads only the supplied clipboard event data and follows the normal attachment limits; the application does not poll your clipboard.

## Troubleshooting

- **Network or CORS error:** Confirm the selected route and connection. In Direct mode the provider must allow browser requests, including preflight and streaming response headers. Browser errors cannot reliably distinguish CORS from other network failures. You can explicitly select a configured gateway. A relay does not bypass provider terms, authentication or access restrictions.
- **Gateway access or verification error:** Check the self-hosted gateway token, or retry the Open 3D gateway verification. The provider key cannot replace a gateway token. Turnstile contacts Cloudflare without sending prompts, images or provider keys to the challenge service.
- **Gateway policy, compatibility or size error:** Check the exact allowed web origins and target URL safety rules and protocol support, update an incompatible gateway, or remove large attachments. These failures do not retry. Both gateway modes support compatible custom public HTTPS providers without a provider-host allowlist.
- **Gateway rate or concurrency limit:** Wait before retrying. Eligible transient relay failures use the same five-retry owner as provider failures, not an additional gateway retry loop. Cancellation stops discovery, verification, authorization exchange and retry waits as well as forwarding where supported.
- **Authentication error:** Recheck the endpoint and key. If the key may have been exposed, revoke it at the provider and remove it from browser settings.
- **Incompatible protocol or tool schema:** Confirm that the endpoint implements the selected native protocol and the model supports streamed tool calling. Some compatible services implement only part of that contract. This is not retried as a transient network error.
- **Retry after failure:** The failed prompt and its images return to the composer only if the AI has not produced non-blank text, valid proposed changes or a successful tool result. Once the AI has responded, the prompt and images remain in the conversation history without being restored to the composer, including when a later continuation fails. Successfully generated changes and their canvas preview remain available, even in Auto-approve mode. Choose **Keep changes** to apply these changes as one undoable edit, or **Discard changes** to clear the preview without editing the document. Resolve this choice before sending another message; neither choice automatically sends a request. Invalid or incomplete individual commands are not retained. Correct provider settings if needed, then retry or send a follow-up. In Auto-approve mode, previously completed and applied batches remain in the scene; use Undo to revert them if needed.
- **Cancelled request:** Cancellation stops the browser request where supported and discards all unconfirmed proposals from that request. Already applied batches remain undoable. Already streamed conversation text remains visible and is included as conversation context when you send another prompt.
- **Image rejected by the provider:** Confirm that the configured model supports image input. Remove unsupported images or switch to an image-capable model before resending.

After a new session's first successful reply, Modra sends a separate short title request through the same configured provider/protocol/route. It includes only bounded first-round prompt and reply text, not images, scene data or tool details. Manual titles are protected; failure keeps the provisional 10-character title. Reopening existing history never repeats this request.
